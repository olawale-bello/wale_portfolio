Problem Statement

Financial fraud remains one of the most costly operational risks in banking — costing institutions billions annually while eroding customer trust. The core challenge is not just detection, but speed of detection. Raw transaction data is noisy, inconsistent, and rarely analysis-ready.

The objective was to design and deploy a reliable cloud data pipeline that could ingest raw banking transaction data, apply systematic data quality rules, engineer meaningful fraud-detection features, and surface actionable insights through an always-on interactive dashboard.

Engineering goal: Reduce time-to-insight on suspicious activity from days to minutes through pipeline automation and pre-computed fraud flags.

Data Quality & Feature Engineering

  • 1

    Deduplication

    Applied ROW_NUMBER() window function partitioned by account, date, and amount to identify and eliminate 30 duplicate records.

  • 2

    NULL Handling

    Systematically replaced all NULL values with domain-appropriate defaults, maintaining referential integrity across all downstream joins.

  • 3

    Negative Value Remediation

    Identified and corrected negative LoginAttempts values — preventing skewed aggregations in fraud scoring logic.

  • 4

    Standardisation

    Applied consistent UPPER() normalisation across categorical text columns to eliminate case-sensitivity issues in GROUP BY operations.

  • 5

    Feature Engineering

    Computed three binary risk flags — SuspiciousLogin (≥3 attempts), HighValueTransaction, and NegativeBalance — enabling real-time fraud filtering in Power BI.

Analytical Insights

ATM + high login attempts = elevated fraud signal. ATM transactions account for the highest volume of both high-value flags and suspicious login attempts. In production, this combination would trigger real-time alerts or transaction holds.

Geographic clustering suggests coordinated activity. Fort Worth consistently appears as the top location across multiple fraud indicators — suggesting either a compromised branch or a targeted fraud ring.

Student segment warrants further investigation. The anomalously high average transaction amount in the student occupation segment is inconsistent with expected spending patterns — a potential indicator of account takeover.

Key SQL Used

-- Duplicate detection using window function WITH CTE AS ( SELECT *, ROW_NUMBER() OVER ( PARTITION BY AccountID, TransactionDate, Amount ORDER BY AccountID ) AS RowNum FROM bank_transactions_dirty ) DELETE FROM CTE WHERE RowNum > 1; -- Feature engineering — fraud signal flags UPDATE bank_transactions_dirty SET SuspiciousLogin = CASE WHEN LoginAttempts >= 3 THEN 'Yes' ELSE 'No' END; -- Verification SELECT COUNT(*) AS TotalRows FROM bank_transactions -- 2,512 SELECT COUNT(*) FROM bank_transactions WHERE SuspiciousLogin = 'Yes' -- 95

Problem Statement

Hospital readmissions within 30 days represent a significant financial and operational burden. Identifying high-risk patients before discharge requires consistent, clean, and timely data flowing through a reliable pipeline.

The objective was to design an automated, repeatable data pipeline that ingests patient records, applies rigorous data quality transformations, loads clean data into Azure SQL on a daily schedule, and enables clinical teams to identify readmission risk patterns.

Engineering goal: Eliminate manual data preparation steps and establish a daily automated refresh cycle — ensuring the clinical dashboard always reflects the most current patient data without human intervention.

Data Quality Management

  • 1

    Deduplication

    Removed 50 duplicate patient records using pandas drop_duplicates() — preventing double-counting in readmission rate calculations.

  • 2

    Missing Value Imputation

    Applied mean imputation for the age column using only positive values. Categorical nulls in gender and insurance_type replaced with 'Unknown'.

  • 3

    Outlier & Negative Value Remediation

    Replaced physiologically impossible negative age and length_of_stay values with column averages — preserving distribution shape without introducing bias.

  • 4

    Normalisation & Acronym Preservation

    Standardised categorical text to Title Case with a custom fix_casing() function to preserve clinical acronyms such as COPD.

Analytical Insights

Diabetes and COPD patients carry the highest structural readmission risk. These chronic conditions require ongoing management — patients discharged without adequate follow-up care are statistically more likely to return within 30 days.

Surgical patients' extended stays indicate complexity — not just recovery time. The longer average length of stay suggests higher procedural complexity and greater post-discharge vulnerability.

Uniform risk distribution across seasons and regions points to systemic drivers. When risk doesn't vary by geography or time of year, it points to structural factors — staffing ratios, discharge protocols, or medication adherence.

Key Python Code

import pandas as pd df = pd.read_csv('hospital_readmission_dirty.csv') df = df.drop_duplicates() # Mean imputation using only valid positive values avg_age = df[df['age'] > 0]['age'].mean() df['age'] = df['age'].fillna(avg_age) df['gender'] = df['gender'].fillna('Unknown') df['insurance_type'] = df['insurance_type'].fillna('Unknown') df.loc[df['age'] < 0, 'age'] = avg_age # Preserve clinical acronyms during normalisation def fix_casing(value): acronyms = ['COPD'] return value.upper() if value.upper() in acronyms else value.title() df['gender'] = df['gender'].str.title() df['primary_diagnosis'] = df['primary_diagnosis'].apply(fix_casing) df.to_csv('hospital_readmission_clean.csv', index=False) print("Final shape:", df.shape) # (8000, 17)
